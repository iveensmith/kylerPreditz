# CLAUDE.md

Football prediction and statistics website. Visitors see today's fixtures with a suggested betting market, odds, and a confidence percentage generated by our own engine — a statistical base model with an AI review layer on top.

**The full specification is in `PROJECT.md`. Read it before starting any phase.**

## Stack

Next.js (App Router) + TypeScript · Tailwind · PostgreSQL + Prisma · API-Football (api-sports.io) · Anthropic Messages API · Paystack · Vercel

## Commands

```bash
npm run dev              # dev server
npm run build            # production build
npm test                 # vitest — prediction engine tests
npx prisma migrate dev   # apply schema changes
npx prisma studio        # inspect the database
npm run sync:fixtures    # manual sync (respects API quota guard)
npm run predict:dry      # run engine against next 48h, print results, write nothing
```

## Working rules

- **Build one phase at a time.** Show the file tree and wait for approval before starting the next phase. Do not skip ahead.
- **No mock or placeholder data past Phase 1.** Every page renders from the database.
- **No `localStorage` or `sessionStorage`.** Server state in Postgres, client state in React.
- **All API-Football calls go through `/lib/api-football/client.ts`.** Never call the API from a page, component, or route handler directly. The client handles caching, retries, and the daily quota guard.
- **Write the prediction engine tests before the engine.** The model in `/lib/predictions/model/` is pure — no DB, no network, no LLM. It takes stats in and returns probabilities out.
- **The AI layer is isolated.** It receives a context packet object and returns JSON. It never queries the database or the football API itself. This keeps it testable against fixture files.
- **Never write an LLM response straight to the database.** It passes through `/lib/predictions/ai/validate.ts` every time — no exceptions, no shortcuts when debugging.
- **Server-render everything public.** No client-side data fetching on first paint; SEO is the whole business model.
- Keep components under 200 lines. Split when they grow past it.
- All secrets in `.env.local`. Keep `.env.example` updated and committed.

## Content rules

Never write "100% sure", "guaranteed win", "fixed match", or "sure win" anywhere in UI copy, meta tags, or blog content. Predictions are statistical estimates. Displayed confidence is capped at 92. The public results archive shows losses as well as wins and is never edited.
